상태: 서버·프런트·관리자 수정본 운영 배포 및 Chrome 카카오 로그인 재QA 실시. 실제 재QA에서 발견한 검색 지도 이동·가격 이력 진입 누락·삭제 안내·AI 식사/음료 구분·짧은 화면의 Invalid164도 추가 수정·재배포했다. 서버 실행`cd66ac2`, 웹/관리자`fb6fe67`. **RELEASE_HOLD 유지**. 소스 수정/자동 테스트와 실제 운영 화면 통과는 구분한다.

## 확정 계약

- 원본 공공 매장 자료와 사용자 자료는 보존한다. 매장별 별도 수정 기록을 공통 조회 경로에 적용한다. 관리자 식별정보와 검토 사유는 공개 응답에서 제외한다.
- `free1~free4` 누락은 false다. 명시적인 무료 메뉴만 0원을 허용한다. 복수/범위 가격의 원문은 보존하고, 필터에는 최저값, 실제 방문에는 별도 결제 금액을 사용한다.
- AI/오늘의 픽/루트 `radiusMeters`: 기본 3000, 1000~15000의 정수 1000 단위. 일반 검색의 기존 거리 선택은 유지한다. 구조화된 검증 매장 ID·메뉴·원가격만 지도 카드에 연결한다.
- 절약 통계의 `startDate`, `endDateExclusive`는 한국 시간의 반개구간이다. 상세 목록도 동일 범위다. 기존 범위 없는 전체 이력 API는 유지한다.
- 정보 신고 승인: `resolution`, `reviewReason`, `expectedRevision`, 허용된 `before`, 확정된 `after`. PRICE / LOCATION / CLOSED / NO_CHANGE. 오래된 변경안과 중복 처리 차단.
- 영수증 심사 후 원본 삭제 정책을 유지한다. 심사 후 서버 재조회로 삭제 상태를 갱신하며, 조회 실패 시 삭제 완료를 추측하지 않는다.
- 추천 루트는 현재 위치→첫 매장→다음 매장 구간별 실행이다. 외부 지도 복귀를 방문 완료로 처리하지 않는다.

## 관리자 화면 계약 (admin-ui-orchestrator → admin-ui-builder)

- 역할: 기존 인증 관리자. 일반 사용자에게 처리 API·내부 사유를 공개하지 않는다.
- 데이터: 신고와 현재 매장, 영수증의 정리 상태, 문의 원문/첨부. 제보·문의 텍스트는 데이터로만 취급하고 HTML을 이스케이프한다.
- 작업: 기존 승인/반려 + 확인된 PRICE/LOCATION/CLOSED/NO_CHANGE. 게시 내용/발송은 자동 반복하지 않는다.
- 확인: 변경 전후와 사유, 별도 승인 확인창. 영구 삭제는 이번 QA의 정확한 대상에 대해 실행 직전 사용자 동의를 받는다.
- 감사/복구: 원본 보존·수정 기록·상태 트랜잭션. 공개 데이터만 바꾸며 전체 DB 롤백을 하지 않는다. 삭제는 되돌릴 수 없음을 안내한다.
- 상태: 로딩/빈 목록/조회 오류/권한 만료/읽기 전용 처리 완료/입력 오류/확인/처리 결과·기록을 유지한다.

## 실제 재QA 제한과 인계

- 위 PASS는 해당 실제 동작의 범위만 뜻한다. 실제 iPhone Safari/Android·유효 영수증 신규 대기 원본과 정상 승인·GPS 성공/경계·새 계정·탈퇴·무료 정상 방문·실제 가격/위치/폐업 수정은 미검증이다. 거짓 매장 정보를 만들거나 QA 사진을 실제 방문으로 승인하지 않았다.
- Chrome100지도동작은25회×선택/배경클릭/정·역방향드래그다. 홈↔마이20왕복마다 연결되고 양수 크기인 지도 요소1개를 확인했다. 줌70회는 최대10까지20회 축소+25회확대/축소쌍이며 짧은 검사다. 지도 객체/힙 메모리 전수 계측이나 장시간 검사가 아니다. 콘솔 새 오류는 없지만 NotoSansKR 글꼴 경고2건이 남아 있다.
- 393×852 도구 에뮬레이션에서 DOM viewport와 Flutter view 배율·캡처 크기가 일치하지 않아 실제 목표 크기 QA는 판정 불가였다. override는 해제했다. 요구4크기 자동 위젯 검증과 실제 화면 검증을 구분하며 크기변경20회는 미실행이다.
