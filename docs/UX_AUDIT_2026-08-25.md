# HowMuch UI/UX audit — 2026-08-25

## Scope

- 운영 Flutter 웹 홈 지도와 관리자 UI
- 공통 Flutter 테마, 모바일 캔버스, 하단 내비게이션
- 390×844 모바일 및 1280×800 데스크톱 기준
- Firebase 키 처리 제외

## Findings

### UX-001 — 좁은 웹 화면에서 캔버스가 실제 폭보다 커질 수 있음

- Severity: P1
- Evidence: Observed in code + deterministic test
- Surface: 모든 `FigmaMobileCanvas` 화면
- Evidence detail: 기존 `viewportWidth.clamp(320, 430)`은 320px 미만 뷰포트에도 320px을 반환했다.
- Impact: 브라우저 확대, 분할 화면, 작은 임베드 환경에서 오른쪽 콘텐츠와 터치 영역이 잘릴 수 있다.
- Resolution: 실제 뷰포트 폭을 유지하고 데스크톱에서만 430px로 제한하도록 변경했다.

### UX-002 — 하단 내비게이션 선택 상태가 색상에만 의존함

- Severity: P1
- Evidence: Observed in code
- Surface: 홈, 탐색, 제보, 리포트, 마이 공통 내비게이션
- Evidence detail: 기존 항목은 `GestureDetector`와 아이콘/문자 색상만 사용했고 `selected` 의미가 없었다.
- Impact: 스크린리더와 색상 구분이 어려운 사용자가 현재 위치를 판단하기 어렵다.
- Resolution: 버튼·선택 Semantics, 잉크 피드백, 선택 배경 pill, 11px 라벨을 추가했다.

### UX-003 — 디자인 값이 화면별로 분산됨

- Severity: P2
- Evidence: Measured in repository
- Surface: Flutter 앱 전반
- Evidence detail: 직접 색상 663개, 숫자 반경 380개, 글자 크기 674개가 검색됐다.
- Impact: 동일한 상태가 화면마다 다르게 보이고 작은 수정의 회귀 범위가 커진다.
- Resolution: 공통 7개 범주의 최소 토큰 계약과 semantic 색상 역할을 추가했다. 기존 값은 화면 수정 시 점진적으로 이전한다.

### UX-004 — 관리자 상태색 대비와 동작 감소 지원이 부족함

- Severity: P2
- Evidence: Observed in code + contrast inference
- Surface: 관리자 통계, 상태 배지, 승인·삭제 버튼
- Evidence detail: 밝은 초록·주황·빨강이 작은 텍스트에도 동일하게 사용됐고 `prefers-reduced-motion`이 없었다.
- Impact: 밝은 화면에서 상태 문자의 식별력이 떨어지고 동작 민감 사용자가 애니메이션을 피할 수 없다.
- Resolution: 텍스트용 어두운 상태색과 채움용 상태색을 분리하고 동작 감소 규칙을 추가했다.

### UX-005 — 데스크톱 앱 프레임이 의도적으로 보이지 않음

- Severity: P3
- Evidence: Observed in live screenshot
- Surface: 430px 제한 Flutter 웹 화면
- Evidence detail: 넓은 배경 중앙에 모바일 화면만 배치되지만 경계·깊이가 없어 미완성 레이아웃처럼 보일 수 있다.
- Impact: 모바일 중심 정책 자체보다 구현 결함으로 오해하기 쉽다.
- Resolution: 데스크톱에서만 미세한 세로 경계와 얕은 이중 그림자를 적용했다.

### UX-006 — 관리자 확인창의 키보드·스크린리더 동작이 불완전함

- Severity: P1
- Evidence: Observed in code
- Surface: 제보·영수증·회원·리뷰·댓글·문의 관리자 작업
- Evidence detail: 기존 확인창은 일반 `div`를 시각적으로 겹쳐 표시해 대화상자 의미, 포커스 격리, 실행 버튼으로의 포커스 복귀가 보장되지 않았다.
- Impact: 키보드와 보조기술 사용자가 현재 작업 맥락을 잃거나 배경 컨트롤로 이동할 수 있다.
- Resolution: 8개 확인창을 네이티브 `dialog`로 전환하고 레이블, 초기 포커스, 닫힘 후 포커스 복귀, Escape·배경 클릭 흐름을 통일했다.
