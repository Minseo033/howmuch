- curl 요청 시작부터 첫 바이트까지 17.640초, 연결 준비 이후 첫 바이트 대기 약 17.535초, 첫 바이트 이후 본문 수신 1.394초, 전체 19.034초.

이 값은 **수정 전 운영 관측**이다. 이전 QA의 16.5초 요청도 같은 원인이었다고 확정하지 않는다. curl 구간은 브라우저 DevTools의 Waiting/Content Download 실측과 구분한다. `catalog_lookup`은 build·ETag를 포함하므로 중복 합산하지 않는다.

이번 변경은 서버 내부 중복 계산·할당을 줄인다. API 필드·가격·전국 표시 수·승인 정책·압축 설정·캐시 만료 정책은 변경하지 않는다. 프론트엔드·네이티브 앱 코드는 수정하지 않는다.

## 변경

1. 매장 식별자 정규화·전화번호·이름/주소 비교 정규식을 미리 컴파일한다. 기존 정규화 규칙과 기본 로케일 동작은 바꾸지 않는다.
2. 원본 설치 시 중복 제거를 위해 이미 계산한 stable ID를 런타임 복사본에 보존한다. 첫 요청과 보정 재구성 때 같은 ID를 다시 해시하지 않는다. 명시된 기존 ID는 유지하고 `cachedBaseStores` 및 갱신/내보내기 스냅샷에는 생성 ID를 추가하지 않는다.
3. 공개 필드 중간 투영에서는 값을 다시 깊은 복사하지 않는다. 중복 필터링 뒤 최종 발행 경계에서 한 번만 재귀적으로 복사·불변화한다. 검토된 영업시간의 중첩 맵/리스트도 외부 입력과 분리한다.
4. ETag는 동일한 전체 공개 JSON을 `DigestOutputStream`으로 SHA-256 계산한다. 전체 JSON 바이트 배열을 별도로 만들지 않으며 해시 입력·ETag 형식은 유지한다. JSON 직렬화 작업 자체를 없앤 것은 아니다.
5. 지도 응답은 불변 공개 스냅샷에 대한 읽기 전용 뷰로 `openingHours`만 숨긴다. 매장마다 해시 테이블 전체를 다시 복사하지 않는다. 원본 entry 순서를 유지하고 keySet·values·entrySet·직접 수정은 불변 규칙을 따른다. source 참조/ETag 기반 무효화와 `-map-v1` 태그를 유지한다.
