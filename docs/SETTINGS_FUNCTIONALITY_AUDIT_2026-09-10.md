# 마이페이지·설정 기능 재점검

- 날짜: 2026-09-10
- 원칙: 기존 화면의 카드, 색상, 간격, 섹션, 하단 메뉴를 유지하고 상태 조회·저장·오류 처리만 보완했다.
- 대상: 마이페이지 설정 카드, 계정 관리, 일반 알림, 가격 알림, 프로필 수정, 회원 탈퇴.

| 항목 | 기존 문제 | 반영 내용 |
| --- | --- | --- |
| 위치 권한 | 마이페이지는 항상 허용으로 보이고 계정 화면은 메모리 상태만 표시했다. | OS·브라우저의 실제 서비스/권한 상태를 조회하고 요청 또는 설정 화면으로 연결한다. |
| 푸시 알림 | 로컬 스위치 값이 실제 기기 등록 성공과 무관했다. | 모바일은 실제 권한과 FCM 토큰 등록 성공을 기준으로 표시한다. 실패한 초기화는 정리해 재시도할 수 있다. 웹은 미지원 사실을 안내한다. |
| 마케팅 수신 | 로컬 값만 바뀌는 목업 동작이었다. | 값을 저장하거나 켜진 것처럼 표시하지 않고 현재 미제공임을 안내한다. |
| 일반 알림 | 저장 중 재실행, 실패 후 초안, 저장 전 이탈 처리가 불명확했다. | 저장 중 입력·중복 요청을 막고, 실패 시 초안을 유지하며, 변경 후 나가기는 확인한다. 시작·종료 시간이 같은 방해 금지는 저장하지 않는다. |
| 가격 알림 | 매장별 순차 저장으로 일부만 반영될 수 있고 빈 찜 목록에서는 조건이 저장되지 않았다. | 찜 매장 수신 여부와 세 조건을 한 번의 원자적 서버 쓰기로 저장한다. 빈 목록도 조건을 저장하고 긴 목록은 기존 카드 영역 안에서 스크롤한다. |
| 서버 응답 | HTTP 200이면 누락 값을 기본값으로 보정할 수 있었다. | 필수 불리언과 시간 형식, 매장 ID, 일괄 저장의 `success: true`를 검증한다. |
| 프로필 공개 | 토글은 저장되지만 공개 콘텐츠에 적용되지 않았다. | 토글이 상태나 API를 바꾸지 않으며 현재 미지원임을 안내한다. 닉네임 변경만 저장하고 자동 추가 동의 요청은 하지 않는다. |
| 회원 탈퇴 | 동의가 기본 체크였고 중복 실행을 막지 않았다. | 동의는 해제 상태로 시작한다. 최종 복구 불가 안내 후 한 번만 삭제 요청하고 완료 시 공용 로컬 세션 정리를 사용한다. |

## 서버 계약

- `PUT /api/notifications/price-alerts/batch`는 세션 사용자 ID만 사용한다.
- 요청한 매장이 모두 사용자의 찜인지 확인한 뒤 Firestore `WriteBatch`를 만든다.
- 잘못된 입력·중복 ID는 400, 찜 소유 불일치는 409, 저장 실패는 500으로 응답한다.
- 매장 수신 여부와 가격 조건이 모두 커밋된 뒤에만 `success: true`를 반환한다.
- 일반 알림 저장은 요청에 없는 가격 조건을 덮어쓰지 않는다.
