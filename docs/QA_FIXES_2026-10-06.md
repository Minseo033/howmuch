## 추가 발견·수정

1. 새 제보 저장 완료 화면이 목록 첫 번째 과거 제보를 표시했다. 제출 ID로 연결하고 모든 서버 저장 메뉴를 표시한다. 다른 과거 제보/무료 4번째 메뉴를 포함하는 회귀 검사 통과.
2. 관리자 처리 직후 상세 재진입이 캐시의 검토 중 상태를 유지했다. 상세 진입에서 조회 1회로 최신 상태를 반영한다. 저장 요청 재시도는 하지 않는다. 실패하면 기존 자료를 보존한다. 수정 전 검사 실패를 확인한 뒤 수정 후 통과.
3. 신고 설명이 일반 정보 행의 한 줄 말줄임을 물려받았다. 해당 행만 줄바꿈해 전문 표시. 최종 17 Pro 실화면 확인.
4. **Chrome 인증 팝업을 닫아도 SDK1.9.5가 취소를 전달하지 않아 로그인 버튼이 대기 상태였다.** 설치된 SDK의 popupLogin은 열린 창 핸들을 버리고 인증 코드를 최대10분 조회한다. 타입 취소만 모의한 기존 검사는 이 미완료 Future를 잡지 못했다. 앱 소유의 웹 계정 팝업 어댑터로 핸들을 보관하되 동일 SDK의 코드 조회·토큰 발급을 사용한다. 250ms 종료 감지, 성공 콜백의 창 닫기/코드 전달 경합에3초 유예, 늦은 응답 무효화·타이머 정리를 검사했다. 각 시도에 새 state/PKCE(S256) 생성. RFC7636 URI, 실제 닫기/재시도, 응답 정체/늦은 코드, 성공 자동 닫기, 닫힌 직후 지연 코드, 실제 통신 실패, 시간 제한의7검사 추가. 수정 전 취소 검사 실패를 확인했다. 네이티브는 기존 SDK 경로 유지. SDK1.9.5를 명시 고정했으며 SDK 갱신 시 프로토콜 재검토 필요. 원문 인증 URL/코드/state/PKCE/토큰은 기록하지 않는다. [카카오 Flutter 공식 안내](https://developers.kakao.com/docs/ko/kakaologin/flutter)와 설치 SDK 코드를 함께 확인했다. 추가 동의 팝업 분기는 아직 실검증하지 않았다.
