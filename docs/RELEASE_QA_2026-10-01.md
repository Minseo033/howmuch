# 운영 출시 QA — 2026-10-01

## 범위와 판정 원칙

- 대상: https://howmuch-zeta.vercel.app 및 /admin.html (운영 사이트).
- 도구: Chrome 실제 화면 조작(CUA), 접근성 트리/DOM, 화면 캡처. 소스는 체크리스트 작성 및 원인 대조에만 사용.
- 사용자: 카카오 로그인 완료. 게스트 이용은 실행하지 않음. 관리자 로그인 성공.
- 사용자 승인: 기능 QA와 데이터 변경. 영구 삭제·탈퇴·약관 최종 동의는 실행 직전 별도 확인 필요. 전체 회원 공지/알림 등 실제 서비스에 영향을 주는 테스트는 발송하지 않음.
- 길찾기·방문 인증을 위한 현재 위치의 얼마고/선택한 지도 서비스 전달은 사용자가 별도로 승인했다.
- 비밀번호·토큰·이메일·정확한 사용자 위치는 보고서에 기록하지 않음.
- 상태: PASS=실제 실행/결과 확인, FAIL=재현된 문제, PARTIAL=일부 단계만 실행, BLOCKED=환경/권한/자료 부족, NOT_RUN=미실행. 자동 테스트/소스 확인을 실제 화면 통과로 대체하지 않음.
- UI audit·UX audit·launch readiness 스킬의 근거/심각도/반응형 기준을 적용. 수정/배포는 이번 QA 요청 범위에 포함하지 않음.

## 진행 상태

> 아래104항목/발견표/변경장부는 수정 전1차 QA 당시 기록이다. 이후 사용자 승인 계획을 구현·운영 배포하고 재QA했다. 최신 수정/실증/미검증 및 동의 후 QA7건 삭제 결과는 [후속 수정 장부](RELEASE_REMEDIATION_2026-10-01.md), 프로젝트현황5-145 참조. 당시 FAIL을 자동으로 PASS로 바꾸지 않는다.

운영 사이트 1차 출시 QA와 보고서 정리를 완료했다. **판정: RELEASE_HOLD(출시 보류)**. 출시 전 우선 수정해야 할 P1 6건, P2/UX 11건, 정책 확인 1건을 기록했다. 모든 버튼·데이터 조합·실기기를 통과했다는 의미는 아니다. 미검증/미실행 범위는 아래에 별도로 남긴다.

관리자 9개 메뉴와 로그인 사용자의 주요 기능을 실제 클릭·입력·스크롤하여 확인했다. Chrome 탭 연결이 후반에 끊긴 뒤 관리자 인증/로그아웃과 AI 질문 칩·새 대화는 동일 Chrome의 실제 창을 CUA로 조작했다. 테스트 데이터 영구 삭제는 동의 대기이며 QA 데이터 정리가 완료됐다고 표현하지 않는다.

실행 기록은 복수 버튼/단계를 묶은 **104항목: PASS81 / FAIL15 / PARTIAL6 / BLOCKED2**다. 독립 테스트 케이스 수나 전체 코드 커버리지가 아니다. 발견 사항17건(P1 6/P2 11)과 정책 확인1건은 한 실행에서 여러 문제를 관찰하거나 여러 실행이 같은 문제를 재현하는 관계이므로 FAIL 행 수와 같지 않다.

- Flutter 입력란의 접근성 노드만 변경된 값이 실제 화면/앱에 반영되지 않는 자동 조작 사례가 있었다. 실제 입력란의 화면 좌표를 클릭하고 키 입력 후 화면·저장 결과까지 확인했으며, 이를 제품 입력 오류로 분류하지 않는다.
- 접근성 근거: 찜 해제 확인 화면은 시각적으로 제목/매장/설명을 표시하지만 접근성 트리에는 취소/찜 취소 버튼만 노출된다. 길찾기 이동수단의 시각적 선택 상태, AI 전송 버튼의 이름도 누락된다. 위 P2 접근성 항목에 포함한다.
- 지도 간헐 오류의 최소 재현 원인은 미확정이다. 빠른 선택→배경 클릭→드래그 한 구간에서 발생했고 천천히 나눈 동일 흐름은 정상이다. 단계 간 DOM/지도 생명주기 및 resize 핸들러를 점검할 근거이며, 메모리 부족이나 특정 지도 SDK 결함으로 확정하지 않는다.
