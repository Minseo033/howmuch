- 최초 대조: 동일 매장+시간 후보 38, 시간 미제공 32, 동일 매장 추가검토 30. 조회 실패 0.

- 최종 **39곳 반영, 61곳 보류**. 반영률 39%는 이 표본에서만 관찰된 값이다. 전국 확보율 또는 매장 직접 확인 정확도가 아니다.
- 조회일은 원문 수정일이나 매장의 직접 확인일이 아니다. 원문의 최신 수정일은 제공되지 않았다. 화면에 `자료 조회`로 명시한다.

## 데이터와 표시

- `howmuch_backend/src/main/resources/store-hours.json`: 검토 완료한 39곳의 시간·출처·조회일. 기존 공공데이터와 별도로 관리해 일일/주간 갱신에 덮어쓰이지 않는다.
- `docs/data/store-hours-pilot-20260912.json`: 100곳의 공개 원문·대조 근거·검토 결과. 원문 전체 응답에 포함된 관련 없는 필드는 저장하지 않았다.
- `scripts/survey-store-hours.mjs`: 순차·저속·100곳 한정 수집. 중간 파일을 남겨 재시작 시 완료된 행은 다시 요청하지 않는다. 실행 시 새로운 날짜별 출력 폴더를 사용한다. 결과는 후보이며 자동 승인하지 않는다.
- 서버: 검토 상태·유효 출처·날짜·중복 ID 검사. 매장 ID와 기존 상호·주소·전화번호가 모두 맞는 자료만 응답에 병합한다. 매장 요청당 외부 호출/Firestore 읽기 없음.
- 화면: 기존 영업시간 행에 원문을 정돈한 시간·휴무·브레이크타임·라스트오더 및 출처·조회일 표시. 공란은 정직한 미제공 안내. 새 불러오기 버튼 없음.
- 90일이 지난 조회일에는 오래된 자료 안내. 이는 정기 재확인 자동화가 아니다.
- 기존 앱 캐시는 영업시간 필드를 버렸으므로 카탈로그 캐시 v2 사용. 향후 데이터 갱신은 기존 6시간 TTL을 따른다.
- 이번 단계는 검토된 **서술형 영업시간**이다. 요일별 계산 스키마, 실시간 영업중/종료 판정, 관리자 수정 UI, 자동갱신 스케줄은 추가하지 않았다. 휴무·날짜 예외를 안전하게 구조화하기 전에는 영업중 판정을 만들지 않는다.
- 대림동꽃돼지는 원문에 개점시간만 있어 마감시간 미제공을 명시한다. 보배네능이백숙의 19:00은 예약 마감시간으로 보존한다. 계절·격주 휴무도 원문 의미를 보존한다.
