## 1. 한눈에 보는 결론

자동 테스트, 웹 릴리스 빌드, 운영 배포 상태와 핵심 조회 API는 정상이다. 홈·검색·매장 상세·마이페이지·제보·문의·관리자 메뉴도 대부분 화면 진입과 데이터 로드가 된다.

그러나 다음 세 항목은 발표 신뢰도와 사용자 데이터 처리에 직접 영향을 주므로 최우선으로 수정해야 한다.

1. 회원 탈퇴 안내는 승인 제보를 익명화해 보존한다고 설명하지만 백엔드는 승인 여부와 무관하게 제보를 삭제한다.
2. 운영 AI 채팅이 실제 요청에서 오류 메시지를 반환한다.
3. 검색이 지도 범위 캐시만 사용하고 `/api/stores/all`은 사용자 승인 매장을 제외해, 존재하는 매장을 전국 검색에서 찾지 못한다.

그 밖에 320×568 온보딩/세션 만료 화면의 조작 버튼 가림, 리뷰 사진 미전송, 영수증 수동 승인 정책 충돌, 작은 화면 overflow, 접근성 라벨 누락이 확인됐다.

## 6. 핵심 재현 근거

### 6.1 개인정보 고지와 실제 삭제 불일치

- `privacy_policy_screen.dart:164-166`: 승인된 제보를 익명화해 계속 활용한다고 안내
- `withdrawal_screen.dart:463`: 승인 제보가 익명화되어 계속 제공된다고 안내
- `FirebaseService.java:1308-1345`: 탈퇴 시 해당 사용자의 `stores_user` 문서를 전부 삭제

### 6.2 전국 검색이 지도 범위 캐시에 묶임

- `search_result_screen.dart:223-238`: `globalAllStores`가 비어 있을 때만 `/api/stores/all` 로드
- `home_map_screen.dart:1196`: 지도 bounds 응답을 같은 `globalAllStores`에 저장
- `FirebaseService.java:357-359`: `/api/stores/all`은 정부 매장만 반환
- 운영 재현: `/api/stores/all`에 있는 `구백년짜장`이 현재 지도 범위 밖에서는 검색 0건

### 6.3 영수증 관리자 수동 승인 정책 충돌

- `web/admin.html:1152-1156`: OCR 미설정 상태를 관리자 확인 대상으로 표시하고 승인 버튼 제공
- `FirebaseService.java:862`: 승인 주체와 무관하게 OCR 증거 검사 호출
- `FirebaseService.java:943-954`: 공급자 미설정 또는 텍스트/가격/날짜가 없으면 승인 거부

### 6.4 작은 화면 레이아웃

- `onboarding_page.dart:200-204`: 남은 공간이 부족해도 artwork 최소 높이를 240으로 고정
- `session_expired_screen.dart:34-38`: 네이티브 높이를 800으로 고정해 하단 버튼 위치 계산
- `report_complete_screen.dart:42-143`: 화면 주요 요소를 고정 좌표 `Stack`으로 배치

## 7. 우선 수정 순서

1. 탈퇴 데이터 정책을 결정하고 개인정보처리방침·화면·백엔드를 일치시킨다.
