## 범위와 판정

- 대상: 운영 `https://howmuch-zeta.vercel.app` 및 `/admin.html`. 현재 웹 기능 배포 기준은 `fb6fe67`, 검토한 로컬 HEAD는 `f6952ec`이다. 이번에는 새 배포 정합성 검사를 다시 실행하지 않았다.
- Chrome 실제 화면에서 버튼을 누르고 목록·시트·입력 화면을 열어 패딩, 마진, 정렬, 겹침, 말줄임, 고정 하단 영역을 확인했다. 사용자 화면은 기존 **카카오 로그인**만 사용했으며 게스트는 실행하지 않았다.
- 기본 비교 크기: 375×812, 768×1024, 1280×800. 추가 스트레스 크기: 320×568, 가격·찜 비교: 393×852. 모든 화면을 모든 크기에서 전수 검사한 것은 아니다.
- 점검 화면: 홈/추천 지도, 검색/필터, 매장 상세, 정보 신고, 매장 제보, 동네 제보/지역 선택, 절약 리포트/목표 설정, 마이, 내 제보, 찜 목록, 알림/공지 전문, 알림 설정, 문의 입력, AI 채팅. 관리자: 대시보드, 제보 관리, 공지 입력, 문의 목록/답변 팝업.
- **핵심 배치 문제 5건 + 다듬기 3항목 발견. 수정 전 상태이며 UI 전체 PASS가 아니다.** 기존 RELEASE_HOLD를 유지한다.
- 코드/운영 자료 수정 없이 검토했다. 제보 제출, 문의 발송, 설정 저장, 찜 해제, 관리자 승인·반려·삭제·공지 등록·답변 저장을 실행하지 않았다. 검색은 기기의 최근 검색 표시를 갱신할 수 있고, 공지 조회에는 읽음 처리가 포함될 수 있다.
- `audit`/`ui-craft` 기준으로 실제 화면 증거와 소스 배치 경로를 연결했다. 기존 AppSpacing/AppSizes, 430px 웹 앱 셸, 파란색·둥근 카드 디자인을 기준으로 평가하며 전체 디자인 교체를 제안하지 않는다.

## 정상 확인과 오탐 제외

- 430px 가운데 앱 셸과 데스크톱 좌우 빈 영역은 기존 제품 정책이다. 불필요한 마진 오류로 판정하지 않았다.
- 마이페이지 기본 카드/3열 바로가기, 내 제보 상태 탭·목록, 제보 폼 기본/가격/사진 영역, 정보 신고 하단 입력 영역은 확인한 폭에서 요소가 겹치지 않았다. 마이 마지막 문의 행은 스크롤로 하단 내비게이션 위까지 올라왔다.
- 매장 상세 메뉴 금액과 전화/가격 제보/방문 인증/길찾기 하단 바는 320px에서 읽혔고, 본문 마지막 리뷰 영역도 스크롤로 확인했다.
- 오늘의 픽 393px 추천 목록과 하단 지도/루트 버튼, 공지 전문 320px의 제목·문단·닫기 버튼, 목표 설정 320px의 금액·요약·저장 버튼이 겹치지 않았다.
- 알림 설정 스위치와 설명, 문의 유형 칩과 입력란, AI 메시지 스크롤/입력바를 확인했다. 실제 모바일 소프트 키보드는 검사하지 않았다.
- 관리자 대시보드 1280px, 제보 관리 375px, 공지 입력 375/768px, 답변 모달 375px의 기본 배치/간격은 확인했다. 관리자 모든 탭·모달·상태의 전수 PASS는 아니다.
- 크기 변경 직후 브라우저 DOM과 캡처 레이아웃이 일시적으로 달라진 경우가 있었다. 재시작/목표 크기 재렌더링으로 구분했다. `17-admin-overflow-768.jpg`는 이전 375px 레이아웃이 남은 캡처라 판정 근거에서 제외했다. 태블릿 페이지 가로 소실로 기록하지 않는다. `05-filter-320.jpg`도 시트 진입 전 최근 검색 화면이므로 필터 문제 증거는 06번을 사용한다.
- 입력 폼/화면 전환 직후의 로딩·애니메이션 중 프레임은 완성 화면의 오류/통과 근거로 사용하지 않았다. 신고 유형 라벨이 일시적으로 깨져 보인 프레임은 지속 재현을 확인하지 못해 확정 문제에서 제외했다.

## 접근성·성능 보조 확인 (전수 검사 아님)

- 관리자 답변 textarea의 눈에 보이는 포커스 테두리, 주요 입력 라벨/필수 표시, 출처·선택 상태의 텍스트/아이콘을 확인했다. 키보드 전체 순서·스크린리더·대비율을 전수 검증하지 않았다.
- 지도 조작 영역은 접근성 이름이 있어도 L01처럼 실제 영역이 겹칠 수 있다. 이번 확인에서 지도 확대/축소의 의미 영역 높이는40px이므로 별도 터치 타깃44px 검사도 후속에 포함해야 한다. 기존 위치/AI 접근성 이름 중복도 남아 있다.
- 관리자 modal pop/toast는 transform/opacity 기반이며 `transition:all`은 확인한 관련 소스에 없었다. AI 화면은 `MediaQuery.disableAnimationsOf` 분기가 있다. 실제 프레임/CPU/메모리 성능 수치는 측정하지 않았다.
- 관리자 reduced-motion 규칙은 존재하지만 모든 animation을 1회로 바꿔 spinner도 멈추게 하는 소스 구조다(`admin.html:379`). 시스템 reduced-motion에서의 실제 로딩 표시 검증은 미실시이며, 정상 로딩 신호 유지 여부를 접근성 후속에서 확인해야 한다.
