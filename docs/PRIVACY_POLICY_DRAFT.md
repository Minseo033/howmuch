## 1-3. 삭제 기능 실측

- **회원 탈퇴**: 마이페이지 → 탈퇴 화면 → "탈퇴 시 데이터가 영구 삭제됨에 동의합니다" 체크 → DELETE /api/user → `deleteUser()`가 users + reviews + stores_user + visits + favorites 삭제 후 건수 반환 → 로컬 세션 삭제.
- **탈퇴 화면 안내 항목**: 내 제보 내역 / 찜한 매장 / 방문 인증·절약 리포트 / 작성한 리뷰·댓글 / 가격 알림 구독 (withdrawal_screen.dart `_DeletedDataCard`)
- **불일치 3건**:
  1. **문의 내역(inquiries)은 탈퇴해도 서버에 남음** (삭제 로직 누락) — 안내에도 없고 실제로도 안 지워짐 → 수정 필요
  2. 안내의 "댓글"은 백엔드 미구현이라 실제 데이터 없음 (형식적 표기)
  3. "가격 알림 구독"은 서버 데이터가 아니라 로컬 설정이라 삭제 대상이 아님
- **어드민 강제 탈퇴**: 동일 로직 (AdminController → deleteUser) — 동일하게 inquiries 누락.

## 1-4. ⚠️ 사용자가 예상 못 할 만한 수집 항목 (따로 짚어야 할 것)

1. **"현재 위치로 설정" 버튼 = 기기 좌표가 카카오 서버로 전송** — 프로필 설정과 커뮤니티 피드의 위치 칩이 카카오 역지오코딩 API를 직접 호출. 사용자는 "우리 앱만 위치를 쓴다"고 생각하지만 카카오에 좌표가 감.
2. **오늘의 픽 화면을 열기만 해도 정확한 lat/lng가 백엔드로 전송** — 저장은 안 하지만 서버(및 호스팅 로그)에 도달. 방침에 "조회 시 전송, 저장 안 함"을 명시해야 정직.
3. **AI 채팅 내용은 Google(Gemini)로 전송** — 사용자가 채팅에 개인정보를 적으면 Google 서버에 감. "AI 답변 생성을 위해 Google에 전송됩니다" 고지 필요.
4. **세션 토큰에 카카오 회원번호가 base64 평문으로 포함** — 암호화가 아니라 서명만 된 형태. 웹에서는 localStorage에 저장돼 브라우저에서 누구나 디코딩 가능.
5. **제보 DTO가 통째 저장되는 구조** — `phoneNumber`(현재 빈 문자열), `imageUrls`(로컬 경로) 필드가 이미 저장 스키마에 존재. 향후 입력 필드 추가 시 검토 없이 수집될 위험.
6. **영수증/메뉴판 사진을 "첨부"해도 서버에 안 감** — 사용자는 인증을 위해 전송된다고 오해할 수 있음 (현재는 로컬 미리보기만). 반대로 말하면 사진 수집 고지 의무는 현재 없음.
7. **iOS에 마이크 권한 문구 존재** (NSMicrophoneUsageDescription) — 실제 마이크 사용 코드 없음 (image_picker 동영상 대비 기본 문구). 앱 심사·방침과 무관하게 불필요한 권한 문구는 제거 권장.
8. **기존 앱 내 개인정보처리방침 화면(privacy_policy_screen.dart)이 사실과 다른 템플릿** — "네이버/애플 로그인"(미구현), "프로필 사진 수집"(미수집), "기기 정보·접속 로그 자동 수집"(미수집), "계약·결제 기록 5년 보관"(결제 없음)이라고 적혀 있음. **이 초안으로 교체 필요.**

### 1. 개인정보의 처리 목적 및 수집 항목

운영자는 다음의 목적을 위하여 개인정보를 처리합니다. 처리하고 있는 개인정보는 다음의 목적 이외의 용도로는 이용되지 않으며, 이용 목적이 변경되는 경우에는 별도의 동의를 받는 등 필요한 조치를 이행할 예정입니다.

**① 회원 가입 및 관리 (카카오 로그인)**
- 수집 항목 (필수): 카카오 회원번호(서비스 내 식별자 `kakao:{회원번호}`로 변환), 이메일 주소
- 수집 방법: 카카오 로그인 SDK를 통한 인증 후 이용자 단말에서 이메일 확인, 프로필 등록 시 서버 저장
- 처리 목적: 회원 식별, 로그인 세션 유지, 회원 탈퇴 처리

**② 서비스 프로필 설정**
- 수집 항목 (필수): 닉네임, 주 활동 동네(행정동 수준)
- 수집 항목 (선택): 관심 카테고리, 이번 달 절약 목표 금액
- 처리 목적: 리뷰·제보 작성자 표시, 지역 기반 매장 추천, 절약 목표 관리

**③ 위치 정보**
- 수집 항목: 단말기 현재 위치 좌표(위도·경도)
- 수집 시점: 홈 지도 이용, 오늘의 픽·AI 루트 추천 조회, 주 활동 동네 "현재 위치로 설정", 커뮤니티 피드 지역 표시 시
- 처리 목적: 주변 착한가격업소 표시, 현재 위치 기반 날씨 연계 메뉴 추천, 거리순 정렬
- **위치 좌표는 서비스 서버에 저장하지 않습니다.** (요청 처리에만 사용 후 폐기)

**④ 이용자 생성 콘텐츠 및 이용 기록**
- 수집 항목: 가성비 매장 제보 내용(매장명·주소·업종·메뉴·가격), 리뷰(별점·내용), 방문 인증 기록(매장·메뉴·실제 결제 금액·절약 금액·방문 시각), 찜한 매장 목록, 1:1 문의 내용

### 8. 개인정보 자동 수집 장치의 설치·운영 및 거부

- **쿠키(cookie)는 사용하지 않습니다.**
- 웹 버전은 로그인 세션 유지와 화면 설정을 위해 브라우저 **로컬 스토리지(localStorage)**에 세션 토큰·온볼딩 완료 여부·알림 설정을 저장합니다.
- **거부 방법**: 브라우저 설정에서 사이트 데이터(로컬 스토리지)를 삭제하거나 차단할 수 있습니다. 단, 차단 시 로그인 상태 유지가 불가능합니다.
- 웹 버전은 Google Fonts(폰트)와 카카오 지도 스크립트를 외부에서 불러옵니다. 이 과정에서 각 사업자의 서버에 접속 정보(IP 등)가 전달될 수 있습니다.

### 9. 개인정보의 안전성 확보 조치

코드 기준으로 실제 적용 중인 조치만 기재합니다:

1. 비밀번호를 수집하지 않고 카카오 소셜 로그인만 사용 (비밀번호 유출 위험 없음)
2. 세션 토큰은 HMAC-SHA256 서명 및 168시간 만료 적용
3. 서버는 카카오 액세스 토큰을 카카오 서버에 직접 검증한 뒤 세션을 발급하며, 클라이언트가 보낸 식별자를 그대로 신뢰하지 않음
4. API 키·DB 인증서 등 비밀 정보는 환경변수/시크릿 파일로 분리 관리
5. AI 채팅 등 일부 API에 이용자별 시간당 호출 횟수 제한 적용
6. **[빈칸: Firestore 보안 규칙은 6주차 과제 — 적용 후 "접근 규칙 설정" 항목 추가]**

## 코드 수정이 필요한 사항 (방침과 무관하게 실제 문제)

1. **탈퇴 시 inquiries 삭제 누락** — `FirebaseService.deleteUser`에 `deleteWhere("inquiries", "userId", firebaseUid)` 추가 필요
2. **기존 방침 화면이 허위 기재** — privacy_policy_screen.dart를 이 초안 내용으로 교체 (네이버/애플 로그인, 프로필 사진, 기기 정보·접속 로그, 결제 기록 5년 보관 등 사실과 다른 항목 존재)
3. **iOS 마이크 권한 문구 삭제 권장** — 마이크 사용 코드 없음
4. **로그인 동의 방식** — "간주" 문구만 있고 명시적 동의 체크 없음. 심사·법적 안정성을 위해 최초 로그인 시 동의 체크 추가 검토
