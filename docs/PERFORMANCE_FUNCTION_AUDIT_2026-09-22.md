# 성능·기능 점검 및 보완 — 2026-09-22

기준 커밋: `5ef6638`. Flutter 화면·상태·통신, 웹 지도·관리자, 백엔드 데이터·외부 연동, 데이터 갱신 스크립트와 CI를 나누어 점검했다. 전체 코드의 무결함을 보증하는 전수 검증은 아니며, 아래 수정과 테스트 범위만 확인했다.

## 반영 내용

- 지도·검색: 매장 거리의 반복 계산과 같은 마커의 재렌더링을 줄였다. 검색 추천 목록을 재사용하고, 같은 메뉴명의 추천은 가장 가까운 매장을 기준으로 정렬한다. 가격 필터는 첫 메뉴뿐 아니라 등록된 메뉴 가격을 고려한다.
- 지도 수명주기: 중복 삽입하던 지도 JavaScript를 단일 구현으로 통합했다. 재진입·종료 시 이벤트, 관찰자와 타이머를 정리하고 늦게 도착한 이전 마커 요청을 무시한다. 드래그·확대축소 알림과 잘못된 지도 영역값 처리도 유지했다.
- 앱 통신: 공통 요청에 대기시간 제한을 적용하고, AI·카탈로그·지도 요청의 개별 제한은 유지했다. 카탈로그 동시 로딩은 하나의 네트워크 요청으로 합친다. Dart timeout은 응답 대기 제한이며 전송 자체의 취소를 보장하지 않는다.
- 백엔드: 전체 공개 매장 응답을 원본 목록 변경 전까지 재사용한다. 원본과 응답은 중첩 데이터까지 불변 복사하며, 캐시 상태는 하나의 객체로 게시해 동시 접근 시 서로 다른 버전이 섞이지 않도록 했다.
- 카카오 연동: 주소·장소·지역 검색 응답에 5분 TTL, 최대 256개 캐시를 적용했다. 만료 항목과 오래된 항목을 정리하고 실패 응답은 저장하지 않는다. 좌표 키는 소수점 5자리로 정규화한다. 동시 쓰기에서도 용량 제한을 지키도록 했다.
- 관리자: 늦은 조회 응답이 다른 화면·다른 사용자 모달·새 로그인 상태를 덮어쓰지 않도록 보완했다. 요청 제한 시간이 본문 다운로드까지 유지되며, 대기 중인 삭제·수정은 원래 대상을 갱신한다.
- Android: 카카오맵·네이버지도 설치 확인에 필요한 앱 조회 선언을 추가했다.
- 데이터 갱신: 잘못된 좌표·중복 식별자·일부 조회 실패·기존 보완 매장 누락 시 데이터 교체를 차단한다. 운영 데이터는 변경하지 않았다.
- 자동 배포 검사: 웹 배포 실패를 성공으로 취급하지 않으며, iOS 검사까지 통과한 뒤 웹 배포가 실행되도록 했다.
