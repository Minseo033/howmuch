> - **제보 삭제·사진 연쇄 삭제**: 사용자 `DELETE /api/report/store/{id}`와 관리자 `DELETE /api/admin/reports/{id}`를 추가했다. 사용자 소유권을 확인하고 Cloudinary 소유 사진을 먼저 삭제한 뒤 관련 댓글·좋아요·알림 구독, 제보 문서와 인메모리 캐시를 정리한다. 사진 삭제가 실패하면 제보 문서를 유지해 재시도할 수 있다.

> - **Firestore 보안 룰**: Flutter가 Firestore 클라이언트 SDK를 사용하지 않는 현재 구조에 맞춰 직접 읽기·쓰기를 전부 차단하는 룰과 배포 문서를 추가했다. Firebase 프로젝트 오배포 방지를 위해 `.firebaserc`는 커밋하지 않았으며 실제 룰 배포는 프로젝트 확인 후 진행해야 한다.
> - **공공데이터 스냅샷 자동화**: 운영 캐시를 Firestore 추가 읽기 없이 내려주는 관리자 API, 1만 건·필수 필드 99% 검증 스크립트, 매주 월요일 03:00(KST) 스냅샷 PR을 여는 GitHub Actions를 추가했다. 기존 무인증 `GET /api/public-data/sync`는 제거하고 관리자 `POST`로 변경했으며 API 키 하드코딩을 `PUBLIC_DATA_API_KEY` 환경변수로 옮겼다.
> - **Cloudinary 모니터링**: 민감 필드를 제외한 사용량만 반환하는 관리자 API와 어드민 대시보드 카드를 추가하고 외부 API 호출을 5분 캐시했다.
> - **통합 안정화**: 회원 삭제 시 누락됐던 문의·댓글·좋아요·구독·알림·설정·제보 연관 데이터까지 정리한다. 백엔드 전체 테스트·클린 빌드, Flutter 전체 테스트 32개, 웹 릴리스 빌드가 통과했다. 정적 분석은 error 0·warning 0이며 기존 info 42건만 남았다.
