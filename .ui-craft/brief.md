## 1. Product purpose

공공데이터와 사용자 제보를 결합해 주변 매장의 실제 가격, 절약 기회, 방문 신뢰도를 지도에서 판단하게 돕는다.

## 2. Primary user

외출 중 스마트폰으로 가까운 가성비 매장을 빠르게 찾고 가격을 비교하는 생활 소비자이며, 웹은 모바일 화면과 데스크톱 브라우저를 함께 사용한다.

## 3. Three to five principles

1. **가격 판단이 장식보다 먼저다.** 매장, 거리, 가격, 데이터 출처가 한눈에 읽히지 않으면 시각 효과를 줄인다.
2. **신뢰의 근거를 숨기지 않는다.** 공공데이터, 사용자 제보, GPS, 영수증 OCR의 차이를 색상과 문구로 분명히 드러낸다.
3. **한 손의 다음 행동이 항상 보여야 한다.** 주요 탐색·제보·인증 동작은 48px 안팎의 터치 영역과 명시적 상태를 가진다.
4. **모바일을 기준으로 만들되 웹을 방치하지 않는다.** 작은 화면은 잘리지 않고, 넓은 화면에서는 앱 프레임이 의도적으로 보인다.
5. **실패 상태도 완성된 화면이다.** 로딩, 빈 상태, 권한 거부, 네트워크 오류에는 원인과 복구 행동을 함께 제공한다.

## 4. Success metric for the surface

사용자가 홈 진입 후 30초 안에 주변 매장 하나의 가격과 출처를 파악하고 상세 보기, 길찾기, 제보 중 다음 행동을 선택할 수 있다.

## 5. Out of scope

- 기존 정보 구조와 라우트 체계를 전면 교체하지 않는다.
- Flutter 외 별도 웹 프런트엔드 프레임워크를 추가하지 않는다.
- 이번 디자인 패스에서 다크 모드를 새로 출시하지 않는다.
- Firebase 키와 인증 비밀값 처리 방식을 변경하지 않는다.
- 관리자 기능 권한이나 운영 데이터 스키마를 넓히지 않는다.

## 6. Learned constraints

- **2026-08-25** — Firebase 키 처리는 UI/UX 개선 범위에서 제외한다. *Why:* 사용자가 명시적으로 별도 처리 대상으로 남겼다.
- **2026-08-25** — 기존 블루 브랜드와 모바일 중심 구조를 보존한다. *Why:* 운영 중인 제품의 기능 QA와 회귀 안정성이 전면 재설계보다 우선이다.

## 7. Fold classes used
